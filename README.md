# wdict

A Linux-first desktop dictionary built with Go, Wails v3 and SvelteKit. Current version: **0.1.0**. Search English words and phrases online, reuse saved results, or download a Wiktionary dictionary in the app for offline use. Queries are sent to the online provider only after an offline and cache miss or an expired cache entry.

## Status

Routine CI checks the Linux build and tests without packaging an AppImage. A manually started release workflow builds an AppImage and attaches it to a GitHub release. macOS and Windows binaries are planned after those platforms have been built and tested.

## Install on Linux

Choose either the ready-to-run AppImage or install from source with Go:

- **AppImage:** Download `wdict-x86_64.AppImage` from the [v0.1.0 release](https://github.com/illescasDaniel/wdict/releases/tag/v0.1.0), then make it executable and run it:

  ```sh
  chmod +x wdict-x86_64.AppImage
  ./wdict-x86_64.AppImage
  ```

  FUSE may be required; alternatively run `./wdict-x86_64.AppImage --appimage-extract-and-run`.
- **Go:** Follow [Install with Go](#install-with-go-linux) below. This builds the executable locally and requires Go, a C compiler and Linux development libraries.

## Build and run on Linux

Install Go 1.26.4 or newer, Node.js 22.17 or newer (Node 24 recommended), and the development packages for GTK 3 and WebKit2GTK 4.1. These are system build prerequisites; the project uses Go modules and project-local npm dependencies, not globally installed Wails or JavaScript tools.

The project pins [Task](https://taskfile.dev/) as a Go tool, so no global Task installation is required. From the repository root, run:

```sh
go tool task setup
go tool task build
./wdict
```

The first `go tool task` invocation downloads and compiles the pinned tool. Run `go tool task --list` to see all available commands.

The `gtk3` tag is needed on systems with GTK 3/WebKit2GTK 4.1 instead of Wails v3's default GTK 4/WebKitGTK 6. The binary embeds the static frontend; after UI changes, rebuild and commit `frontend/build` alongside the source. CI verifies the generated assets are up to date. macOS and Windows builds have not yet been verified.

For checks:

```sh
go tool task test
```

## Install with Go (Linux)

Install Go 1.26.4 or newer, a C compiler, `pkg-config`, and the GTK 3 and WebKit2GTK 4.1 development packages. Then run:

```sh
go install -tags gtk3 github.com/illescasDaniel/wdict@v0.1.0
wdict
```

Go installs the executable to `GOBIN` (normally `~/go/bin`), which must be on your `PATH`. GTK and WebKit libraries must also be installed at runtime. The frontend is embedded; Node.js is not needed for `go install`. This does not create a desktop launcher. The `gtk3` tag selects GTK 3 / WebKit2GTK 4.1; macOS and Windows installation have not yet been verified.

## Build a Linux AppImage

On Linux, install the build prerequisites above, plus `pkg-config`, `file`, `find`, librsvg and GObject Introspection development files. Run:

```sh
go tool task appimage
```

The script installs frontend dependencies locally, builds the app and invokes the pinned Wails v3.0.0 generator. It downloads linuxdeploy and writes `dist/wdict-<architecture>.AppImage`; the linuxdeploy download tracks its continuous release, so builds are not fully reproducible. Run the image after making it executable (`chmod +x dist/*.AppImage`). FUSE may be required; alternatively run with `--appimage-extract-and-run`.

Build on an appropriately old supported Linux distribution for wider compatibility: system library versions from the build host affect which other distributions can run the image. The bundled GTK/WebKit stack and its licenses should be reviewed before distribution. Offline dictionary data remains in the user's data directory, outside the AppImage.

## Preparing a release

Before a release, update `VERSION`, the frontend package version and lockfile, and the matching dated section in `CHANGELOG.md`. Commit these changes to `main` and ensure CI passes. Start the **Release** workflow on `main` with the matching version (for example `0.1.0`). It validates the version and release notes, runs the checks, builds a Linux AppImage, creates the `v`-prefixed tag and publishes a GitHub release with the AppImage attached. Do not run it until the release is ready; macOS and Windows binaries are not yet generated by this workflow.

If publishing fails after the tag is pushed, inspect the existing tag and release before retrying; the workflow refuses to reuse an existing tag. The version tag also makes the Go module available to Go tooling. Release versions must not be retagged after publication.

## Data and sources

The app offers the pinned [20261018 English Wiktionary StarDict release](https://github.com/xxyzz/wiktionary_stardict/releases/tag/20261018), compiled by [xxyzz](https://xxyzz.github.io/wiktionary_stardict/) from [Wiktionary](https://en.wiktionary.org/). Its package metadata identifies the snapshot as [CC BY-SA 4.0](https://creativecommons.org/licenses/by-sa/4.0/); credit belongs to Wiktionary contributors and xxyzz. wdict extracts definitions and changes their formatting. The download is approximately 142 MB, is user initiated, and is verified against the publisher's SHA-256 checksum before installation.

Online lookups use [Free Dictionary API](https://dictionaryapi.dev/). The app displays each response's supplied source and license links; sampled responses identified [CC BY-SA 3.0](https://creativecommons.org/licenses/by-sa/3.0/). Offline results link to their Wiktionary source and license, and the offline dictionary screen also links to its source and license. Wiktionary may contain material from other sources with separate requirements; see [Wikimedia's reuse terms](https://foundation.wikimedia.org/wiki/Policy:Terms_of_Use).

Offline dictionary data is stored separately from the disposable response cache, in the user's data directory. Inflected-form resolution and spelling suggestions are planned for later.
