Failure inventory

  • F1: invalid input shows validation without network or dictionary I/O; correct and retry.
  • F2: a French provider fails or returns ambiguous data: use stale French data if available; otherwise report unavailability with retry while keeping other results. Existing silent-failure handling remains applicable.
  • F3: a reliable French miss is distinct from unavailability; other results remain. Only show a total miss when all languages reliably miss.
  • F4: a dictionary or voice download, integrity or installation error reports failure and allows retry; installed dictionaries and voices remain usable.
  • F6: an unavailable or timed-out French alternatives scan returns no partial ranking and leaves other results usable; retry after the dictionary is available. Suggestions are possible matches, not guaranteed morphological relations.
  • F5: if the French Piper voice is absent or fails, use French eSpeak fallback where available; if playback ultimately fails, report failure and retain the definition. A voice download failure remains retryable and preserves installed voices.

Proposed decisions

  • Success: each query searches all three languages independently, labels and attributes results, and allows French interface selection, including app-generated dates. French pronunciation uses the existing play controls: optional Piper speaks available IPA, followed on absence or failure by French eSpeak IPA mnemonics and then the headword. Source recordings are not downloaded. An optional French Piper voice pack follows the existing packs. After a confirmed French miss, suggest possible base forms and spelling candidates from the installed French dictionary.
  • Recovery: preserve completed results, stale fallback and per-language retries; a newer search supersedes older work. Failed dictionary or voice installation preserves working data. Missing or failed Piper falls back to eSpeak; an ultimate playback failure is reported.
  • Performance and resources: concurrent independent results; reuse current request, cache and archive safeguards where appropriate. French dictionary and voice package sizes, parser cost, alternatives scan cost and coverage, synthesis performance and added memory are unmeasured; measure before setting thresholds, retaining the existing shared runtime budget.
  • Trust boundary: validate input before I/O; treat provider text, links and archives as untrusted. Use fixed sources, safe text rendering, validated attribution, pinned verified packages and safe extraction. Confirm dictionary and voice source rights, attribution, data quality, French phoneme support and IPA conversion and normalization; pin and verify the voice package before offering it. French conversion and voice support remain unverified.
  • Compatibility and rollout: retain existing English and Spanish dictionaries, caches and preferences; add French separately. Dictionary and Piper voice installation are optional and user initiated; rollback leaves existing data usable. No release is implied.

Scope

In scope: automatic French lookup, interface translation, source attribution, French eSpeak pronunciation, an optional French Piper voice, French alternatives after a confirmed miss, and an optional French offline dictionary if suitable verified packages exist. Alternatives require that dictionary, use bounded regular-form rules and spelling search, and only return verified headwords; the actual French rules and coverage need evaluation, and no separate morphology dataset is assumed. Candidate sources and formats require investigation; a missing suitable source or voice requires revisiting the design. Out of scope: translation between languages and adding a search-language selector.

Detailed report

Contracts and five decisions

  • Success criteria: Every valid search starts three independent language lookups; each completed result is labeled with its language and applicable source, license, origin and stale indication. Interface language controls app copy and app-generated dates, not dictionary definitions. The selected language appears first and the other two follow English, Spanish, French order. French selection persists. An explicitly installed French dictionary works after restart.
  • Failure handling: Each language independently tries offline data, fresh cache, online provider, then stale cache on online failure. Retry only the failed language; preserve successful groups and prior-result behavior. HTTP 502 keeps the existing silent temporary failure behavior, without caching a miss; show the existing temporary-unavailability message when no result or visible failure supersedes it. Only three reliable misses yield total not-found. New work supersedes stale search, retry and alternatives outcomes. Failed installs preserve installed data. Missing or failed Piper falls back to French eSpeak; ultimate failure is displayed without hiding the definition. Failed or incomplete alternatives publish no partial ranking.
  • Performance and resources: Apply existing 10-second online timeout and 2 MiB response cap, 365-day cache freshness, 20-minute dictionary download timeout and 1 GiB extraction cap. Alternatives use a 2-second deadline, 64-Unicode-scalar query maximum, 128 MiB index-read cap, at most five spelling candidates and bounded retained state; the 64 MiB additional shared-heap figure is a measurement target, not a hard cap. Voice downloads retain the 150 MiB per-file cap and synthesis the 10-second timeout. Measure French package sizes, first and repeat lookup latency, concurrent heap, scan coverage and pronunciation before release; these measurements are not latency guarantees.
  • Trust boundary: Validate UTF-8 and a trimmed 1–256-scalar query with no control characters before I/O. Use fixed HTTPS providers, encoded titles, French-only extraction rendered as plain text, and validated attribution links. Catalog IDs select pinned packages; verify exact bytes, SHA-256, provenance and rights, reject unsafe paths and invalid content, and install atomically. Never accept a UI-supplied URL or path. Verify model and configuration suitability, phoneme coverage, license and attribution before offering the voice. Alternatives read only the local French index and send no additional query.
  • Compatibility and rollout: Preserve English and Spanish dictionary paths, provider and cache identities, language preference and voices; keep French dictionary, cache and voice separate. No data migration or automatic download. Rollback leaves older data usable. If suitable French sources or voice cannot be verified, stop and revisit the design instead of silently shipping narrower support.

French alternatives use nonrecursive, deliberately incomplete regular-form rules: strip a final s or x, or replace final aux with al; retain only nonempty candidates found in the installed French index. Preserve ambiguity and label suggestions as possibilities. Evaluate representative regular, irregular, accented and ambiguous cases against the selected dictionary; no separate morphology dataset is in scope.

Source and release blockers: French provider and parser feasibility, French-only extraction, source and package licenses and attribution, exact sizes and hashes, dictionary samples, voice model/configuration provenance and phoneme coverage, and pronunciation quality remain unverified and must be verified before implementation. A source or voice that cannot satisfy these checks requires revisiting the approved design.

Given / When / Then scenarios

S1 · Independent results

Given all three sources have entries, when a valid query runs, then each completed language group appears without waiting for the others, with language, attribution, origin and stale status as applicable; selected interface language is first, followed by the remaining languages in English, Spanish, French order.

S2 · French interface

Given French is selected as interface language, when the app restarts and results are shown, then French remains selected, app controls and app-generated dates use French, and source definitions stay in their original language.

S3 · Invalid input · F1

Given the trimmed query is empty, invalid UTF-8, over 256 Unicode scalar values or contains a control character, when the user submits it, then validation appears and no lookup, network, dictionary, cache, pronunciation or alternatives operation starts.

S4 · Independent failure · F2

Given French is unavailable and another language succeeds, when results arrive, then the successful group remains visible; French stale data is shown as stale if available, otherwise French offers retry without repeating successful languages.

S5 · Silent HTTP 502 · F2

Given French returns HTTP 502 with no stale result, when the search settles, then it is not cached or treated as a miss; existing silent-unavailable behavior applies and, if no result or visible failure supersedes it, the temporary-unavailability message appears.

S6 · Miss versus failure · F2, F3

Given a reliably parsed response has no French section, when French lookup completes, then it is a miss; malformed, ambiguous, oversized or failed responses are unavailable, and a total miss is shown only when all three reliably miss.

S7 · Supersession

Given a search, retry or alternatives scan is pending, when a newer search or retry supersedes it, then late outcomes from the older attempt cannot replace current results.

S8 · Offline and cache

Given the installed French dictionary contains a headword, when it is searched after restart, then the offline result avoids an online request; otherwise a fresh French cache hit avoids online I/O and cannot collide with English or Spanish records.

S9 · Dictionary installation · F4

Given the user explicitly downloads French dictionary data, when network, integrity, extraction or validation fails, then the failure is shown with retry and existing dictionaries remain usable; a successful retry verifies and installs atomically.

S10 · Voice installation · F4

Given the user explicitly downloads the French Piper voice, when model or configuration download, verification or installation fails, then no partial voice is offered, existing voices remain usable and retry is available; missing runtime prerequisites retain the existing disabled state and explanation.

S11 · French pronunciation · F5

Given a French result offers playback, when play is selected, then installed Piper synthesizes supported shown IPA where available; otherwise or on failure, French eSpeak tries IPA mnemonics and then the headword. Ultimate failure is reported while the definition remains. Source recordings are never downloaded. Spelling playback uses eSpeak for the headword. Playback uses the native host player with the existing webview fallback.

S12 · French morphology

Given a confirmed French miss and readable installed French index, when the alternatives scan completes within its budget, then nonrecursive base-form candidates generated by stripping final s or x or replacing final aux with al have nonempty stems, are shown only if the headword exists in the index, and have duplicate display strings removed; fixtures include chats → chat and chevaux → cheval.

S13 · French spelling alternatives

Given a confirmed French miss and readable installed index, when the alternatives scan completes within budget, then existing Unicode folding and accent-insensitive optimal-string-alignment distance at most two produce deterministic ranking, preserve displayed accents and phrase distinctions, and return at most five spelling candidates.

S14 · Alternatives unavailable · F6

Given the French offline dictionary is missing, the index is unreadable or oversized, the query exceeds 64 Unicode scalars, or the scan times out, when alternatives would run, then the appropriate missing, unavailable or timed-out state is shown, the lookup remains intact, and no partial candidates are published.

S15 · Untrusted inputs and artifacts

Given provider markup, invalid attribution links, unsafe package paths, an unknown catalog ID or a bad checksum, when the app processes them, then markup is not executed, invalid links are not invented, unsafe installation is rejected and existing data is preserved.

S16 · Compatibility and rollback

Given existing English and Spanish dictionaries, caches, voice packs and saved language are present, when the app is upgraded and later rolled back, then existing data and behavior remain usable and unchanged; French data may remain on disk without damaging older behavior.
