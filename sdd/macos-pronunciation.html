Detailed report

Flow and failure paths

User requests pronunciation → existing synthesizer produces WAV → player adapter selects an available host player and supplies the temporary WAV as a single argument → playback completes → temporary file is removed.

F1: player absent: try the next available candidate. F2: player returns an error: try remaining candidates, then return the existing playback failure if none succeeds. F3: cancellation: terminate the child and remove the temporary file.

Walkthrough

Success

macOS with afplay: synthesize WAV, call afplay with the file path, remove the file after completion.

F1 · no player

No usable candidate: existing unavailable result; no retained temporary file.

F2 · player fails

Try the next available player; if none succeeds, return the existing error.

F3 · cancellation

Stop the child and remove its temporary WAV.

Proposed decisions

  • Success: afplay receives a valid WAV path on macOS, with no mandatory third-party player.
  • Failure and recovery: retain existing fallback and error behavior for F1–F3.
  • Performance: retain current synchronous player lifecycle; measure regressions rather than invent a latency limit.
  • Trust boundary: execute a discovered executable with an argument vector, never a shell; preserve private temporary-file permissions and cleanup.
  • Compatibility and rollout: add a macOS candidate without changing Linux precedence; no data migration; revert the change if needed.

Scope

In scope: native macOS playback selection and tests. Out of scope: changing synthesis, voices, packaging, Windows support, or UI design. No open design questions.
