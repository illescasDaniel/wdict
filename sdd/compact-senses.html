The source is Spanish Wiktionary: touch; regional and colloquial labels present in the available data must remain with their senses; recovering labels absent from the extracted source is outside this layout change.

Proposed decisions

  • Success: adjacent matching senses share one heading and one continuous list; separate entries and nonmatching contexts remain separate.
  • Failures and recovery: unknown part of speech does not establish equivalence; render separately. Existing lookup errors and retry behavior remain intact.
  • Performance: process senses in source order in one pass; no new network requests. Numeric timing and memory budgets await measurement.
  • Trust boundary: dictionary text and metadata are external input; preserve existing safe rendering and avoid treating content as markup.
  • Compatibility and rollout: presentation-only change; keep the data and source boundaries intact, with existing behavior restorable by reverting the change.

Scope

In scope: compact presentation of adjacent compatible senses, preserving all labels and examples. Out of scope: changing source data, translating meanings, deduplicating, merging separate entries, changing lookup or pronunciation behavior.

Proposed interface changes

SenseGroup is optional, opaque provenance, not display text, a credential, or a globally stable identifier. Equal nonblank tokens authorize joining only adjacent meanings with exactly equal nonblank supplied part of speech inside the same entry. A missing token leaves the existing meaning as one group, including any definitions already in that meaning. Arrays, strings, counts and order stay unchanged in storage and transport.

{"PartOfSpeech":"Sustantivo masculino","Definitions":["Comentario breve, digresión."],"SenseGroup":"p0:g1"}

Legacy JSON omits the field. The helper makes one forward pass using append operations, does not mutate input or perform I/O, and returns source-ordered display meanings. Dynamic frontend/src/lib-api.js forwards data; this application path needs no generated bindings.

Evidence production and trust boundary

The existing spanishMeanings(root *html.Node, offline bool) ([]core.Meaning, int) signature stays unchanged. Extend heading state to track actual section, definition heading and consecutive run. Assign the same local token only to consecutive valid numbered definitions under confirmed shared heading and context, whether in one definition list or adjacent sibling lists. Every later run gets a fresh token even when text matches.

Invalidate the run on every heading, including identical headings; an h4 may establish the next supplied heading, while other headings cannot inherit part of speech as evidence. Also invalidate on entering or exiting an actual section without restoring the prior run, language transition, pronunciation or etymology boundaries outside a definition, intervening nondefinition content, unfamiliar containers that prevent proof of adjacency, missing or blank headings, malformed or unpaired numbering, interrupted or empty candidates, and a new extraction or payload. Whitespace and transitions between adjacent definition lists do not alone break a confirmed run. Descendants within a consumed definition retain existing extraction behavior. Preserve Spanish section counting and errors; uncertainty means a split.

Offline Find accumulates word.Data payloads: namespace every nonempty local token by payload ordinal before append, for example p0:g1 and p1:g1. Online Spanish parses one document and tokens are unique within its entry. External content remains text and existing source-link validation remains in force. Existing extracted presentation strings are the fidelity boundary: recovering source labels is out of scope.
