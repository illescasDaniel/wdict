Five proposed decisions

  1. Success: exact raw spelling including case ranks first, then case-insensitive raw, then accent/punctuation folded, then alias. Direct headwords precede weaker aliases. Within equally strong ambiguous case matches, prefer ordinary lexical entries over exclusively proper nouns; unknown part of speech is neutral. Remaining ties are stable.
  2. Failure and recovery: preserve existing offline/online fallback, loading, empty, error and retry behavior. Missing IPA is explicit; unknown grouping identity stays separate. User-requested reading uses existing playback availability, error, retry and exclusivity behavior.
  3. Performance: rank only candidates already obtained and use no new I/O for ranking or grouping. Measure before setting numeric time or memory budgets; do not invent a threshold.
  4. Trust: source content is untrusted; safely render text and validate links using existing protections. Never fabricate IPA or borrow it from differently cased entries.
  5. Compatibility and rollout: apply deterministic query-aware ordering when results are delivered, including legacy cache hits, without mutating cached arrays. Offline cache keys fold case and take priority; online cache keys use NFC casefold. Both require consistent query-aware presentation while preserving fallback and freshness. Exact implementation and migration are deferred to architecture.

Grouping and pronunciation boundaries

Group only records with the exact same headword and case, language, and known source identity. Keep every source record visibly distinct within its card, with its own IPA and etymology where supplied; never flatten or deduplicate meanings. Missing or unknown source identity remains separate.

When a record lacks IPA, the proposed explicitly routed headword-reading mode uses existing eSpeak spelling synthesis if available, only on user request. It does not download a model or make a network request. This reading can sound like the common word and does not guarantee the pronunciation of a proper name or accent. Existing eSpeak fallback reads headword text; Piper uses IPA. The label must distinguish synthesized reading from source pronunciation.

Out of scope: automatic online enrichment, new downloads or models, synthetic phonetic spelling, and changing dictionary contents. No additional I/O is introduced except user-requested playback.

Detailed report

Five decisions and contracts

  1. Success and ordering: trim the current query using existing validation. Rank only returned candidates: exact headword spelling and case; Unicode case-insensitive raw match; existing StarDict accent/punctuation fold; then all indirect, alias-only, unknown and otherwise unmatched records. Use the strongest direct query/headword correspondence even if an alias also points to the record. Preserve order within each tier except the case-insensitive preference below. Legacy results cannot distinguish alias from other unmatched entries; both share the final tier, after direct matches. No alias provenance recovery or metadata is required.
  2. Failure and recovery: preserve existing lookup freshness, fallback, loading, empty, partial, error and retry behavior. On missing IPA show the localized source-unavailable copy and an explicit spelling-reading action. Missing engine uses the existing localized no-source playback message and retry; synthesis failure uses existing no-synthesis; decoding failure uses existing localized playback-failed. Latest request wins across sourced IPA and spelling reading; completion, failure and cancellation clear playback state.
  3. Performance and resources: rank and group existing candidates only, with no added filesystem, network or synthesis calls. Only user-requested spelling playback invokes local synthesis; lookup I/O follows existing policy. Existing lookup validation bounds input. Measure representative candidate counts with elapsed time, allocations and environment before and after; no unmeasured timing SLA is asserted.
  4. Trust and validation: safely render source text and validate links under existing protections. At 320px in light and dark themes, no horizontal page overflow; all record sections and controls remain usable with keyboard, accessible names and inline errors. Do not invent IPA or source metadata.
  5. Compatibility and rollout: identical query-aware ordering applies to fresh, offline in-memory, online, memory, disk, stale and legacy deliveries wherever applicable. Ranking and grouping must not mutate cached arrays or nested content. No freshness or fallback policy changes and no candidate enrichment.

Case-insensitive preference

Normalize each POS label by trimming, collapsing whitespace and Unicode casefolding. Proper labels: proper noun, nombre propio, sustantivo propio, sustantivo propio masculino, sustantivo propio femenino. Ordinary labels: noun, verb, adjective, adverb, pronoun, determiner, article, preposition, conjunction, interjection, numeral, particle, sustantivo, sustantivo masculino, sustantivo femenino, sustantivo masculino y femenino, verbo, adjetivo, adverbio, pronombre, determinante, artículo, preposición, conjunción, interjección, numeral, partícula.

An entry is ordinary if it has at least one recognized ordinary label and no unknown label, including a mixture of known proper and ordinary labels. It is proper only when it has at least one proper label and all labels are proper. Empty labels or any unknown label are neutral; do not infer from substrings. In the case-insensitive tier retain neutral records at their original positions and stably partition the remaining known slots into ordinary then exclusively proper. Exact, folded and final tiers retain stable order.

Grouping and source content

A known source requires nonempty Source.ID and Source.URL. Group records anywhere in the ranked list only when exact headword including case, language and all source fields including attribution, license and additional URLs are equal. Missing identity stays separate. The card occupies its first member’s position and its sections follow ranked member order: A1, B, A2 becomes A(A1, A2), B. Thus later sections may move across other cards; global record order is not promised. Every original record remains visible, with its meanings, POS, pronunciation labels/audio and attribution; no flattening or deduplication. Existing compact sense grouping stays within the original record context. Preserve currently available metadata; do not invent etymology labels or recover raw omitted labels. Never borrow IPA across records, including identical headwords; identical-IPA suppression must not make a record with its own IPA look unavailable.

Missing pronunciation

For each record without valid source IPA, English displays “Pronunciation unavailable in this source”, “Read word aloud”, and “Synthesized from spelling; source pronunciation unavailable”. Spanish displays “Pronunciación no disponible en esta fuente”, “Leer palabra en voz alta”, and “Voz sintetizada a partir de la escritura; pronunciación de la fuente no disponible”. Only a user action routes the exact headword to eSpeak SpeakText using defaults en-us or es. No Piper, IPA inference, new model or network is involved. Existing sourced pronunciation keeps existing behavior. Spelling reading cannot guarantee proper-name or accent correctness.

S7: Nonadjacent grouping

S8 (F2): Conservative grouping

Given missing source ID or URL, or differing case or language, when grouped, then those records stay separate.

S9 (F3): Source IPA boundaries

S10 (F3): Missing IPA presentation

Given a record with no valid IPA, when displayed in English or Spanish, then its specified localized copy and button appear and playback does not start automatically.

S11 (F3): Spelling reading

Given the user activates spelling reading, when synthesis is requested, then eSpeak SpeakText receives the exact headword and en-us/es default, with no network, Piper, model download or invented IPA.

S12 (F4): Playback recovery

Given unavailable engine, synthesis failure, decoding failure or competing IPA and spelling requests, when playback is attempted, retried or cancelled, then the specified existing localized error appears as applicable, latest request wins and state clears on completion, failure or cancellation.

S13 (F1): Lookup failure

Given lookup fails, when stale fallback is available or unavailable, then existing fallback or localized error and retry behavior applies.

S14: Existing states

Given loading, empty or partial results, when rendered, then existing states remain and no result is invented.

S15: Safe responsive access

Given unsafe text and links and multiple record sections, when rendered and operated by keyboard at 320px in light and dark themes, then existing safe text/link handling applies, all sections and controls are usable with accessible names and inline errors, and the page has no horizontal overflow.

S16: Resource measurement

Given representative candidate counts, when rank/group runs, then no added filesystem, network or synthesis calls occur and before/after elapsed time, allocations and environment are reported without asserting an unmeasured SLA.
