# `go vet -tags integration` blocked by a pre-existing copylocks finding

On 2026-11-13, while adding the audio-pronunciation integration tests, `go vet -tags integration ./internal/adapters` failed on a pre-existing `copylocks` issue at `internal/adapters/installer_lifecycle_test.go:273` (a lock copy in existing test code, unrelated to the new work). Impact: anyone adding integration-tagged tests gets a vet failure that looks like their own; the project gate (`go tool task test`) does not run vet with the integration tag, so the gate stays green and the problem only surfaces on manual vet runs. Reproduction: `go vet -tags integration ./internal/adapters` on main after v0.7.1. Suggested fix: correct the lock copy in `installer_lifecycle_test.go` (small, mechanical) or document the exemption. Not verified: whether the same finding appears without the integration tag (the plain gate does not include vet).
