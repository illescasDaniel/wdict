# SDD inline renders in T3 Code showed broken when passed as a file path

On 2026-11-13, in a T3 Code session (model provider opencode-go), the sdd-html-feature Design render point was passed to `html_render` as a `path` pointing at the `inline_view.py` output wrapped in a minimal document shell (`/tmp/opencode/audio-design-wrap.html`). The user reported the page "didn't render correctly inline", and said the same failure had happened in other sessions that used opencode models. `html_preview` on the same file rendered correctly (contentHeight 1216, valid screenshot), so the document itself was fine — the failure is specific to the inline attachment pipeline, not the HTML.

Fix that worked: call `html_render` with the same content passed as the inline `html` string (fragment wrapped in a `<!doctype html>` shell, built in the Code Mode runtime); the tool accepted it and rendered. So for T3 Code render points, prefer `html_render(html: ...)` with the exact `inline_view.py` output (glance-only copy under 12 KB, byte-for-byte, only wrapped in a doctype shell for the renderer) instead of `html_render(path: ...)` to a temp file. Caveat: the Code Mode runtime has no filesystem access, so the fragment text must be read (read tool) and embedded in the call.

Impact without the fix: the reviewer cannot judge a gate from the chat render — the skill's whole reporting path breaks, silently (the tool still returns success with an attachment id). Verified 2026-11-13: only the `path` variant was reported broken by the user; the inline `html` variant was confirmed good by the user's request being about the earlier render. Not verified: whether `path` fails always or only for /tmp files outside the workspace, and whether other providers' sessions passed inline html (explaining "only opencode models").

## Correction (same day, after retest)

The inline-`html` "fix" was wrong. The user's screenshot showed the reply with **no frame at all** above it: `html_render` attachments are not displayed in this client for opencode-provider model sessions — neither the `path` variant nor the inline-`html` variant — while both calls return success with an attachment id, and `html_preview` on the same document renders correctly. The failure is silent: do not trust `html_render`'s success return as evidence the user saw anything.

Working replacement (verified 2026-11-13): use the skill's own fallback, `inline_view.py <page> <tab> --format md`, and paste its Markdown output verbatim in chat; the user confirmed it displays. Optionally open the full page with `browser.preview` (Review pane) for the rich view. Scope (user, same day): this applies **only when the agent model is from the opencode provider running in T3 Code**; Claude Code and Codex render `html_render` correctly in their own harnesses, so their render points must not be degraded to Markdown.
